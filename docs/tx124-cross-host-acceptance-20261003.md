# tx50 到 tx124 的 MySQL 跨主机恢复与复制验收

记录日期：2026-10-03。源主机为 `tx50`（CentOS 7.6，x86_64），目标主机为 `tx124`（Ubuntu 24.04.4，x86_64）。这次使用本地演示平台和两台测试主机，验证 MySQL 跨 Agent 逻辑恢复和自动 GTID 基线。

## 主机与连接

`tx124` 的 SSH 主机指纹为 `SHA256:9UPYXh5MMLlgq4ZbATT5JLjXb/0fHUq2Tfk96xuUcYQ`。纳管前在目标机读取 SSH host key 并核对指纹。平台主机和 Agent 均为 #76，`dbops-agent.service` 已启用。Agent 使用持久凭据连接本地演示平台，一次性 bootstrap token 已删除。平台地址经 [SSH 反向隧道](demo-reverse-ssh-tunnel.md)提供。

目标机原有的 `aim-mysql-3319.service` 继续运行。新主机恢复使用端口 13310；复制验证使用独立的空白实例 13311 和 13313。新实例位于 `/opt/dbops/mysql/<端口>`，各使用独立的 systemd 服务。安装前确认端口空闲、根分区约有 31 GiB 可用空间。13310、13311 使用 128 MiB Buffer Pool 和 50 个最大连接；13313 使用 64 MiB 和 30 个连接。

验收后，tx124 根分区约有 28 GiB 可用空间。`dbops-mysql13310.service`、`dbops-mysql13311.service`、`dbops-mysql13313.service`、`aim-mysql-3319.service` 和 `dbops-agent.service` 均为 active。四个 MySQL 实例同时运行时，内存约有 449 MiB 可用，swap 已用约 1.1 GiB；后续负载测试前需复查资源。测试失败现场位于 `/opt/dbops/mysql/13310.failed-task24-20261003`；排查结束前保留。

## 公网地址与跨主机复制

2026-10-03 复测发现，先前的公网超时探测用了错误的目标地址 `43.130.6.50`，不能代表 tx50。SSH 别名 `tx50` 实际指向 `81.70.17.50`。从 tx124 和 tx180 均能连接 `81.70.17.50:13307`；创建复制用户前，MySQL 分别返回 `Host '43.130.6.124' is not allowed` 和 `Host '43.159.45.180' is not allowed`。这说明软件防火墙入口已连通，数据库当时尚无对应来源授权。

平台登记的 tx50 主机地址仍是内网 `10.2.4.16`，tx124 连接 `10.2.4.16:13307` 会超时。复制表单现允许填写副本可访问的主库 IPv4 地址；本次使用 `81.70.17.50`。平台仍按目标主机地址 `43.130.6.124` 创建专用复制用户授权，未放宽为任意来源。

平台任务 #29 在 tx124 安装空白 MySQL 13311，登记为实例 #6。自动基线任务 #30 完成主库预检、跨 Agent 导出和导入 GTID 快照、创建复制用户与配置复制，但首次核查时 IO 线程仍为 `Connecting`，任务因此失败，未登记拓扑。MySQL 日志随后记录副本成功连接 `81.70.17.50:13307` 并启动 GTID 复制。代码已将创建后的核查改为最多等待 120 秒。

核对 #30 已导入的基线与连接状态后，任务 #31 以“人工已准备一致基线”模式重新配置并登记复制关系 #3。主库为 tx50 实例 #2，副本为 tx124 实例 #6；IO 和 SQL 线程均为 `Yes`，延迟 0 秒。主库新增 ID 6 后，副本备份任务 #32 读到相同的 6 条记录。平台重启副本任务 #33 成功，复制刷新仍为健康。主库再新增 ID 7，副本备份任务 #34 读到 7 条记录；`super_read_only=ON` 已持久化。原有 MySQL 3319 和独立恢复实例 13310 保持运行。

任务 #37 在 tx124 安装另一空白 MySQL 13313，登记为实例 #7。任务 #38 使用 `auto_baseline=true` 和公网主库地址，一次完成源库与副本预检、GTID 快照导出、跨 Agent 传输、导入、复制用户创建、复制配置、健康核查和拓扑登记。复制关系 #4 的 IO/SQL 均为 `Yes`，延迟 0 秒。主库新增 ID 8，副本备份任务 #39 读到 8 条记录。副本重启任务 #40 成功，主库再新增 ID 9，副本备份任务 #41 读到 9 条记录；刷新后复制仍健康，`super_read_only=ON` 已持久化。这次用全新空白副本验证了完整自动任务一次成功。
